# joinrpg-infrastructure

Инфраструктура JoinRPG и соседних проектов (КогдаИгра, рейтинг Бастилии, Twilight, справочник, сайты игр) в публичном облаке Селектел, описанная в Terraform.

Всё, что здесь описано, меняется **только через код**. Правка в панели Селектела станет расхождением с кодом, и следующий `terraform apply` её откатит.

## Что где лежит

Каждый каталог — отдельный слой со своим файлом состояния. Номер задаёт порядок зависимостей: слой опирается только на слои с меньшим номером.

| Слой | Что в нём |
|---|---|
| [`00-tfstate-bucket`](00-tfstate-bucket) | бакет `joinrpg-tfstate`, в котором лежит состояние всех слоёв |
| [`01-network`](01-network) | сеть `joinrpg-network`, подсеть `192.168.0.0/24`, роутер |
| [`02-k8s`](02-k8s) | кластер Kubernetes `joinrpg` и группы нод |
| [`03-databases`](03-databases) | управляемый PostgreSQL (кластер, базы, пользователи), ВМ `mssql-prod` с MS SQL, её диск, публичный адрес и группа безопасности |
| [`04-storage`](04-storage) | бакеты S3 и реестр контейнеров `joinrpg` |
| [`05-dns`](05-dns) | DNS-зоны и записи |

Общие файлы в корне:

- [`secrets.env.example`](secrets.env.example) — шаблон файла с доступами;
- [`selectel-mirror.tfrc`](selectel-mirror.tfrc) — зеркало провайдеров Terraform: `registry.terraform.io` из России недоступен.

Все ресурсы живут в пуле `ru-6`. Манифесты и чарты для кластера в этом репозитории не хранятся.

## Подготовка

1. **Terraform.** Проверено на версии 1.16.5. Ставится с зеркала Селектела: `https://mirror.selectel.ru/3rd-party/hashicorp-releases/terraform/`. Команды ниже — для bash (Linux или WSL).
2. **Сервисный пользователь Селектела** с ролью `member` в проекте и его S3-ключ. Выдаёт владелец проекта.
3. **Файл доступов.** Скопируйте `secrets.env.example` в `secrets.env` в корне репозитория и заполните. Файл в `.gitignore`, в репозиторий не попадает. Пароли пользователей PostgreSQL в нём нужны только слою `03-databases`.

Перед работой в каждом новом терминале:

```bash
source <(tr -d '\r' < secrets.env)
```

`tr` убирает переводы строк Windows, если файл редактировался там.

## Как вносить изменения

```bash
cd 05-dns            # нужный слой
terraform init       # один раз для каталога
terraform plan
terraform apply
```

- Перед `apply` прочитайте итоговую строку плана. Если в ней есть `destroy` или `must be replaced`, а вы этого не ждали — не применяйте.
- После `apply` повторный `terraform plan` должен показать `No changes`.
- Не запускайте `apply` в одном слое одновременно с кем-то ещё: блокировки состояния нет.

### Частые задачи

- **DNS-запись.** Файл `05-dns/zone-<зона>.tf`, ключ записи — `"<полное имя с точкой>/<тип>"`. Значения TXT пишутся в кавычках внутри строки: `"\"v=spf1 ...\""`.
- **Доступ к ВМ MS SQL с нового адреса.** Список `mssql_ingress_rules` в `03-databases/locals.tf`.
- **Новый бакет.** Список `buckets` в `04-storage/locals.tf`. Тип бакета (публичный или приватный), класс хранения и привязка домена через S3 API не задаются — их настраивают в панели.
- **Домен для бакета.** Бакет должен быть публичным. Сначала добавьте в `05-dns` запись `CNAME` на `access.ru-6.storage.selcloud.ru.` (панель при привязке проверяет именно это значение, на основной домен бакета `<uuid>.selstorage.ru` привязать не даст), примените, затем привяжите домен и выпустите TLS-сертификат в панели. Если записи ещё нет, панель создаст её сама — и она разойдётся с кодом.

## Импорт ресурсов, созданных в панели

Если ресурс всё-таки создали в панели, его нужно описать в коде и забрать в состояние блоком `import` (пример — `05-dns/imports.tf`). После успешного `apply` блоки `import` можно удалить.

Провайдеру `selectel` для импорта нужны переменные окружения: `OS_DOMAIN_NAME` и `INFRA_PROJECT_ID` (есть в шаблоне `secrets.env.example`) и `INFRA_REGION`. Последнюю задают вручную в терминале, потому что значение зависит от слоя:

```bash
export INFRA_REGION=ru-6   # кластер, базы, реестр
export INFRA_REGION=ru-1   # DNS: в каталоге пула ru-6 нет адреса DNS API
```

## Что нужно знать про код

- **`ignore_changes` после импорта.** Ресурсы создавались в панели и были импортированы. Часть параметров провайдер при импорте не восстанавливает, и без `ignore_changes` Terraform пересоздал бы ресурс. Закрыты: размер нод кластера, публичный адрес и пулер PostgreSQL, сеть, диск и метаданные ВМ `mssql-prod`, адрес и группа безопасности её порта. Причины и как снять ограничение — в комментариях рядом с каждым блоком.
- **`prevent_destroy`.** Кластер PostgreSQL, его базы, ВМ `mssql-prod` и её диск защищены: план, в котором они удаляются или пересоздаются, Terraform выполнять откажется.
- **Пароли пользователей PostgreSQL** Terraform не меняет. Они используются только при создании пользователя, менять их нужно в панели.
- **Балансировщик кластера** создаёт сам Kubernetes для `Service` типа `LoadBalancer`, в Terraform его нет.
- **Доступ к базам через балансировщик кластера** (176.53.231.74, `joindb.tsarevs.ru`) — исключение из правила «только через код». Слушатели `joindb-mssql` (1433 → MS SQL), `joindb-psql` (5433 → мастер PostgreSQL) и `joindb-ssh` (2222 → SSH ВМ MS SQL) заведены вручную через `openstack loadbalancer`, вход ограничен списком адресов на слушателях (`allowed_cidrs`). Что нужно помнить:
  - балансировщиком управляет Kubernetes: после смены нод или правки `Service traefik/traefik` проверьте, что слушатели `joindb-*` на месте; при удалении `Service` пропадёт весь балансировщик;
  - бэкенд PostgreSQL задан IP-адресом мастера. После переключения мастера его нужно перебить на адрес, который даёт `master.4b8029b8-1433-4452-b2e3-e171e7212ec6.c.dbaas.selcloud.ru`;
  - когда появится репозиторий с чартами, слушатели переносятся в TCP-входы traefik, а ручные удаляются.
- **Состояние** лежит в бакете `joinrpg-tfstate`, по файлу на слой. Версионирование в бакете выключено, блокировки нет. В состоянии хранятся чувствительные данные, доступ к бакету давайте так же осторожно, как к паролям.
